# 上游对齐文档

本目录记录本仓库（湖南大学校内版，远端 `XiaooYi/hnu-ragent`）与上游开源项目 `nageoffer/ragent` 的**分叉判定、功能差异和逐项落地过程**。

上游持续迭代，本仓库是在某个时间点分叉后独立演进的分支。要回答“上游比我们多什么”“我们该按什么顺序补齐”，必须先固定分叉点，再按分叉点之后的上游提交做差异清单。

| 文档 | 内容 |
| --- | --- |
| [`fork-divergence.md`](fork-divergence.md) | 分叉点判定结论、证据和复核方法 |
| [`feature-gap.md`](feature-gap.md) | 上游分叉后新增/增强的功能清单、我方现状、优先级 |
| [`roadmap.md`](roadmap.md) | 分批实施顺序、依赖关系和落地状态跟踪 |
| [`features/`](features/) | 每个功能的实现文档：功能介绍、验收标准、代码位置、相关图表 |

## 使用约定

1. 实现任何一项功能前，先在本目录的 `features/` 下补齐该功能文档，再写代码。
2. 功能文档必须包含四节：**功能介绍**、**验收标准**、**代码位置**、**相关图表**。
3. 功能落地后回到 [`roadmap.md`](roadmap.md) 更新状态，并把实际落地的类、配置项、测试写回对应功能文档。
4. 如果落地过程中改变了检索顺序、阈值、TopK、状态语义或数据结构，必须同步 `docs/rules/`、`docs/database/` 和对应测试。
5. 上游实现只作为参考：本仓库的模块边界（`bootstrap` / `framework` / `infra-ai` / `mcp-server`）、中文提示词风格和校内业务场景优先，不做无必要的架构搬运。
