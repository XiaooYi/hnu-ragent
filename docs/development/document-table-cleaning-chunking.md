# 文档表格清洗与分块待办

## 背景

- 当前分块结果中出现 `<table>`、`<tr>`、`<td>`、`rowspan`、`colspan` 等 HTML 控制信息。
- 表格被当成普通字符串交给通用 chunk splitter，导致表格在行或单元格中间被截断。
- 前端分块编辑页面直接展示了未经结构化处理的表格内容。
- 项目已经存在 Excel 处理逻辑，需要基于实际调用链确认它与 Word 表格、通用分块器之间的关系，避免重复实现。

## 目标

- 表格向量化内容不再包含 HTML 控制标签和布局属性。
- Word 表格和 Excel 表格按完整行、表头和表格语义分块。
- 每个表格 chunk 都能独立理解，并能定位回原始文档、工作表或单元格范围。
- 普通段落继续使用现有文本分块逻辑。
- 保留原始解析结果，支持问题排查和重新处理。

## 一、确认现有代码链路

- [ ] 定位文件上传后的文档解析入口。
- [ ] 定位 Word、Excel、PDF 各自的解析器或加载器。
- [ ] 定位 Excel 已有处理逻辑，确认输出是纯文本、HTML、`Document`，还是其他中间结构。
- [ ] 定位通用文本分块器及其调用位置。
- [ ] 确认 `IngestionNode` 的执行顺序和节点排序方式。
- [ ] 确认 chunk 实体、DTO、向量化输入和前端编辑接口使用的字段。
- [ ] 确认现有 chunk 最大字符数或 token 配置。
- [ ] 确认是否已经保存页码、工作表名、单元格范围等来源元数据。

## 二、建立结构化文档块

- [ ] 将解析结果区分为标题、段落、表格、图片等块类型。
- [ ] 不再把整个 Office 文档拼接成单一字符串后再进行通用分块。
- [ ] 在通用文本分块之前增加表格识别和表格规范化节点。
- [ ] 保留标题路径、表格标题、说明文字和单位等上下文。

建议处理顺序：

```text
文档解析 → 结构识别 → 表格规范化 → 表格分块 / 普通文本分块 → Embedding → 向量入库
```

## 三、清洗 Word 表格

- [ ] 如果当前解析结果是 HTML，使用 HTML 解析器读取完整的 `<table>` 节点，不使用正则直接截取。
- [ ] 读取 `<tr>`、`<td>`、`<th>`，建立二维表格结构。
- [ ] 先根据 `rowspan` 和 `colspan` 还原单元格位置。
- [ ] 结构还原后，再删除 `rowspan`、`colspan`、`style`、`class` 等控制信息。
- [ ] 解码 `&#x20;`、`&nbsp;` 等 HTML 实体并清理多余空白。
- [ ] 识别表头，无法识别时默认使用第一行作为表头。
- [ ] 对合并单元格进行语义化处理：分类字段可以向下填充，视觉标题不要盲目复制。
- [ ] 将表格前的标题、说明和单位附加到每个表格 chunk。
- [ ] 输出 Markdown、规范化文本或结构化 JSON，禁止将原始 HTML 直接送入 embedding。

目标格式：

```text
表格：差旅报销标准

列：职级 | 城市级别 | 住宿上限 | 交通标准

经理 | A 类城市 | 500 元/晚 | 高铁二等座
```

## 四、表格专用分块

- [ ] 普通文本继续使用现有文本分块器。
- [ ] 表格使用独立的表格分块器。
- [ ] 小表格在 token 预算允许时整体作为一个 chunk。
- [ ] 大表格按完整数据行切分。
- [ ] 每个 chunk 重复表格标题、表头、单位和必要说明。
- [ ] 禁止在 `<tr>`、行记录或逻辑数据组中间截断。
- [ ] 单行超过 token 上限时，只对超长单元格进行二次切分，并重复列名和行标识。
- [ ] 表格 chunk 不使用普通正文的 overlap，依靠重复表头保持上下文。
- [ ] 保存表格行范围，例如 `row_start`、`row_end`。

## 五、复核并复用 Excel 现有逻辑

- [ ] 以现有 Excel 解析代码为准，不重复新增 Excel 解析器。
- [ ] 确认 Excel 是按工作簿、工作表、连续数据区域还是行记录拆分。
- [ ] 确认空行、空列、合并单元格和隐藏工作表的现有处理方式。
- [ ] 确认公式使用计算结果、公式文本，还是两者同时保存。
- [ ] 如果 Excel 已经生成结构化行列数据，优先复用该结构处理 Word 表格。
- [ ] 如果 Excel 也生成 HTML，抽取公共的表格 HTML 规范化和表格分块能力。
- [ ] 每个 Excel chunk 重复工作表名称、表头和数据范围。
- [ ] 保存 `sheet_name`、`cell_range`、`row_start`、`row_end` 等元数据。

Excel 目标格式：

```text
工作簿：销售数据.xlsx
工作表：2025年第一季度
区域：A1:H30

列：日期 | 区域 | 产品 | 销量 | 销售额
2025-01-01 | 华东 | 产品 A | 120 | 35,000 元
```

## 六、数据模型和前端兼容

- [ ] 区分原始解析内容和规范化内容，例如 `raw_content`、`normalized_content`。
- [ ] Embedding 和前端分块编辑使用规范化内容。
- [ ] 原始内容只用于调试、重新处理和源文档追溯。
- [ ] 增加或复用 `block_type`、`table_index`、`heading_path`、`source_page`、`sheet_name`、`cell_range`、`row_start`、`row_end`、`bbox` 等元数据。
- [ ] 确认旧 chunk 数据是否需要重新处理。
- [ ] 前端展示时渲染规范化表格，不显示 HTML 原文。
- [ ] 保证已有普通段落 chunk 的编辑、启停和批量操作不受影响。

## 七、PDF 页眉页脚清洗

- [ ] PDF 解析时保留页码、文本块坐标和页面信息。
- [ ] 识别页首、页尾的重复文本作为页眉页脚候选。
- [ ] 对页码、日期和流水号做归一化后再判断重复。
- [ ] 仅删除跨多数页面重复且位置稳定的页眉页脚。
- [ ] 首页标题和章节标题不能仅凭一次出现就删除。
- [ ] 删除正文中的页眉页脚，但保留 `source_page` 元数据。
- [ ] 多栏 PDF 先恢复阅读顺序，再执行正文分块。

## 八、测试

- [ ] 普通无合并单元格的 Word 表格。
- [ ] 同时包含 `rowspan` 和 `colspan` 的 Word 表格。
- [ ] 表格跨多个 chunk 时每个 chunk 都有完整表头。
- [ ] 连续出现多个 Word 表格。
- [ ] 表格前带标题、说明和单位。
- [ ] HTML 实体、空单元格和多余空白。
- [ ] 单行内容超过 token 上限。
- [ ] Excel 多工作表和多个连续数据区域。
- [ ] Excel 合并单元格、公式、日期、金额和百分比。
- [ ] PDF 重复页眉、页脚和页码。
- [ ] 重新处理后，旧的普通文本 chunk 行为不变。
