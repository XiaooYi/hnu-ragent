# 企业内部文档问答场景 MCP 工具设计

## 背景

Ragent 的主场景是企业内部文档问答与知识检索，知识库适合承载相对稳定的内容，例如制度文档、操作手册、FAQ、流程说明、系统使用规范等。

MCP 工具不应该重复做知识库检索，而应该补充知识库无法稳定覆盖的动态信息、个性化信息和结构化业务数据。例如用户问“我还有几天年假”“我的报销单到哪一步了”“我名下有哪些设备”“这个系统权限该找谁开通”，这些问题只靠文档无法准确回答，需要实时查询 HR、OA、ITSM、资产、财务等内部系统。

因此，企业内部文档问答场景下，推荐将 MCP 定位为：

- 查询动态业务状态
- 查询个人相关数据
- 查询内部系统结构化数据
- 执行低风险辅助操作
- 与知识库答案形成组合回答

## 不建议继续使用的示例工具

当前项目中的 `weather_query`、`sales_query`、`ticket_query` 更适合演示 MCP 的调用链路，但和企业内部文档问答主场景不够贴合。

- `weather_query`：天气查询偏通用生活服务，和企业知识问答关系弱。
- `sales_query`：销售数据查询更像 CRM/BI 场景，除非项目定位是销售运营知识助手。
- `ticket_query`：工单查询有一定企业场景价值，但当前实现偏客户技术支持工单，不如改成企业内部 IT 工单。

## 推荐 MCP 工具清单

### 1. `employee_directory_query` 员工与组织架构查询

**场景定位**  
查询员工、部门、岗位、直属上级、办公地点、联系方式、部门负责人等组织信息。

**典型问题**

- “张三是哪个部门的？”
- “财务共享中心负责人是谁？”
- “我想申请发票抬头变更，应该联系哪个部门？”
- “信息安全问题应该找谁？”

**建议参数**

| 参数 | 类型 | 说明 |
|---|---|---|
| `keyword` | string | 员工姓名、部门名称或岗位关键词 |
| `queryType` | string | `employee`、`department`、`owner` |
| `department` | string | 可选，限定部门范围 |

**返回内容**

- 员工姓名
- 工号脱敏
- 部门
- 岗位
- 直属上级
- 办公地点
- 企业邮箱
- 业务负责人信息

**适合配合的知识库文档**

- 组织架构说明
- 部门职责说明
- 常见事项联系人清单

### 2. `leave_balance_query` 假期余额查询

**场景定位**  
结合 HR 制度文档，查询员工个人年假、调休、病假额度和已使用情况。

**典型问题**

- “我今年还有几天年假？”
- “我入职 3 年，年假怎么算？”
- “我这个月还能请调休吗？”
- “请年假需要提前多久申请？”

**建议参数**

| 参数 | 类型 | 说明 |
|---|---|---|
| `userId` | string | 当前登录用户 ID，默认从上下文获取 |
| `leaveType` | string | `annual`、`compensatory`、`sick` |
| `year` | integer | 查询年份 |

**返回内容**

- 假期类型
- 总额度
- 已使用天数
- 剩余天数
- 到期时间
- 数据更新时间

**适合配合的知识库文档**

- 年假制度
- 请假流程
- 考勤管理办法

**组合回答方式**

知识库回答“制度规则”，MCP 回答“个人余额”。例如：

> 根据公司年假制度，年假申请需提前 1 个工作日提交。你当前 2026 年剩余年假为 4.5 天，其中 2 天将在 2026-12-31 到期。

### 3. `approval_status_query` OA 审批状态查询

**场景定位**  
查询请假、报销、采购、合同、权限申请等 OA 流程状态。

**典型问题**

- “我的报销单审批到哪一步了？”
- “采购申请为什么还没通过？”
- “合同审批现在卡在哪个人？”
- “我上周提交的权限申请有没有通过？”

**建议参数**

| 参数 | 类型 | 说明 |
|---|---|---|
| `userId` | string | 当前用户 ID |
| `processType` | string | `leave`、`expense`、`purchase`、`contract`、`permission` |
| `status` | string | `pending`、`approved`、`rejected`、`all` |
| `dateRange` | string | 查询时间范围 |
| `keyword` | string | 单号、标题或关键字 |

**返回内容**

- 流程单号
- 流程标题
- 当前节点
- 当前处理人
- 当前状态
- 提交时间
- 最近更新时间
- 驳回原因

**适合配合的知识库文档**

- OA 审批流程说明
- 报销制度
- 采购制度
- 合同审批规范

### 4. `it_ticket_query` 内部 IT 工单查询

**场景定位**  
替换当前偏客户支持的 `ticket_query`，改成企业内部 IT 服务台工单查询。

**典型问题**

- “我的 VPN 工单处理到哪了？”
- “电脑蓝屏报修有没有人接单？”
- “上周提交的邮箱权限申请完成了吗？”
- “IT 工单一般多久能处理？”

**建议参数**

| 参数 | 类型 | 说明 |
|---|---|---|
| `userId` | string | 当前用户 ID |
| `category` | string | `account`、`network`、`device`、`software`、`permission` |
| `status` | string | `pending`、`processing`、`resolved`、`closed` |
| `ticketNo` | string | 工单号 |
| `limit` | integer | 返回条数 |

**返回内容**

- 工单号
- 问题分类
- 当前状态
- 处理人
- 优先级
- SLA 截止时间
- 最近处理记录

**适合配合的知识库文档**

- IT 支持 FAQ
- VPN 使用手册
- 邮箱配置指南
- 设备报修流程

### 5. `asset_query` 办公资产查询

**场景定位**  
查询员工名下电脑、显示器、手机、工牌、门禁卡等办公资产。

**典型问题**

- “我名下有哪些办公设备？”
- “我的电脑什么时候到期更换？”
- “资产转交需要走什么流程？”
- “显示器坏了，是走报修还是资产更换？”

**建议参数**

| 参数 | 类型 | 说明 |
|---|---|---|
| `userId` | string | 当前用户 ID |
| `assetType` | string | `laptop`、`monitor`、`phone`、`card`、`other` |
| `status` | string | `in_use`、`repairing`、`returned` |

**返回内容**

- 资产编号
- 资产类型
- 品牌型号
- 领用时间
- 使用状态
- 保修截止时间
- 是否满足更换条件

**适合配合的知识库文档**

- 办公设备领用制度
- 资产归还流程
- 设备维修流程

### 6. `permission_owner_query` 系统权限与负责人查询

**场景定位**  
查询内部系统权限申请入口、审批负责人、权限说明和开通条件。

**典型问题**

- “我想开通 GitLab 权限找谁审批？”
- “生产数据库只读权限怎么申请？”
- “CRM 系统销售主管权限需要哪些条件？”
- “哪个系统支持 SSO 登录？”

**建议参数**

| 参数 | 类型 | 说明 |
|---|---|---|
| `systemName` | string | 系统名称，例如 GitLab、OA、CRM |
| `permissionName` | string | 权限名称 |
| `queryType` | string | `owner`、`apply_path`、`required_materials` |

**返回内容**

- 系统名称
- 权限名称
- 权限负责人
- 审批链路
- 申请入口
- 所需材料
- 安全等级

**适合配合的知识库文档**

- 权限管理制度
- 内部系统清单
- 账号安全规范

### 7. `document_version_query` 制度文档版本查询

**场景定位**  
查询制度文档的最新版本、发布部门、生效时间、历史版本和废止状态。

**典型问题**

- “现在最新的报销制度是哪一版？”
- “这个差旅标准是 2024 版还是 2025 版？”
- “旧版考勤制度还有效吗？”
- “薪资福利政策最后更新时间是什么时候？”

**建议参数**

| 参数 | 类型 | 说明 |
|---|---|---|
| `documentName` | string | 文档名称或关键词 |
| `department` | string | 发布部门 |
| `status` | string | `effective`、`expired`、`draft` |

**返回内容**

- 文档标题
- 当前版本
- 生效时间
- 发布部门
- 负责人
- 是否有效
- 历史版本列表
- 文档链接

**适合配合的知识库文档**

- 所有制度类文档
- 文档元数据表

**说明**

这个工具非常适合 RAG 场景，因为企业内部文档经常存在版本冲突。知识库负责回答内容，MCP 负责确认“哪一版是最新有效版本”。

### 8. `expense_status_query` 报销与发票状态查询

**场景定位**  
查询员工报销单、发票抬头、发票状态、打款状态等财务流程数据。

**典型问题**

- “我的差旅报销什么时候打款？”
- “发票抬头在哪里查？”
- “这张发票有没有被占用？”
- “报销被驳回是什么原因？”

**建议参数**

| 参数 | 类型 | 说明 |
|---|---|---|
| `userId` | string | 当前用户 ID |
| `expenseNo` | string | 报销单号 |
| `invoiceNo` | string | 发票号码 |
| `status` | string | `draft`、`pending`、`rejected`、`paid` |
| `dateRange` | string | 时间范围 |

**返回内容**

- 报销单号
- 报销类型
- 金额
- 当前审批状态
- 打款状态
- 驳回原因
- 发票校验状态

**适合配合的知识库文档**

- 报销制度
- 发票管理规范
- 差旅标准

## 推荐优先级

如果只做 3 个最贴合企业内部文档问答的 MCP 工具，建议优先实现：

1. `approval_status_query`：覆盖 OA、报销、请假、采购、合同等高频动态状态查询。
2. `it_ticket_query`：贴合企业内部 IT 支持与系统使用手册场景。
3. `document_version_query`：解决制度文档版本冲突，是 RAG 项目很容易讲出亮点的工具。

如果要做 5 个工具，追加：

4. `leave_balance_query`：体现“制度文档 + 个人数据”的组合回答能力。
5. `permission_owner_query`：适合和内部系统权限制度、账号安全规范结合。

## 与现有 RAG 链路的结合方式

现有链路可以保持不变：

```text
用户问题
  -> 问题重写与拆分
  -> 意图识别
  -> 命中 KB / MCP / SYSTEM 意图
  -> KB 多路检索 + MCP 工具调用
  -> 上下文格式化
  -> LLM 生成回答
```

关键是调整意图树配置：

- KB 意图：制度解释、流程说明、FAQ、手册问答。
- MCP 意图：个人余额、审批状态、工单状态、资产状态、权限负责人、文档版本。
- SYSTEM 意图：问候、能力说明、澄清反问、非业务闲聊。

## 示例意图映射

| 用户问题 | 意图类型 | 推荐工具 | 是否需要 KB |

## 面试回答模板

可以这样介绍：

> 项目里的 MCP 不是用来替代知识库检索的，而是补充企业内部文档问答中“动态数据”和“个人数据”的部分。比如制度文档能告诉用户年假怎么计算，但不能知道用户还剩几天年假；报销制度能说明审批流程，但不能知道某张报销单当前卡在哪个节点。因此我把 MCP 工具设计为 OA 审批状态、IT 工单、文档版本、假期余额、权限负责人、资产信息等内部系统查询能力。RAG 负责回答稳定规则，MCP 负责补充实时状态，最终由 LLM 把两类上下文融合成自然语言答案。

## 简历描述建议

原描述可以从：

> MCP 工具调用

改成：

> MCP 工具调用：接入企业内部 OA、ITSM、HR、资产和文档元数据等动态数据源，支持审批状态、IT 工单、假期余额、权限负责人、制度版本等实时查询；通过 LLM 参数抽取和工具结果格式化，将结构化业务数据与知识库检索结果融合生成回答。

如果需要更简洁：

> MCP 动态工具：设计 OA 审批、IT 工单、假期余额、权限负责人、文档版本等企业内部 MCP 工具，补充知识库无法覆盖的实时状态和个人数据。
