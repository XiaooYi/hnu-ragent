# Ragent 验收用例模板

按需求选择适用项，并在下方追加需求专用用例。这里的用例是验收清单，不替代 `bootstrap/src/test`、`frontend/tests` 或集成环境的自动化测试。

## 后端与数据

| 用例 ID | 用例名称 | 验收标准 |
| --- | --- | --- |
| BACK-001 | 参数校验与统一异常 | 缺失或非法参数返回稳定错误响应，不泄露堆栈且不出现未处理的 500 |
| BACK-002 | 幂等与并发协调 | 使用现有幂等、锁或信号量机制的请求重复执行时，不产生重复数据或资源泄漏 |
| BACK-003 | 数据库升级 | 新部署的 `schema_pg.sql` 与已部署实例的升级脚本都可达到目标结构，关键查询和索引可用 |
| BACK-004 | Redis 失败语义 | 缓存、限流、锁或会话协调不可用时，行为与该组件的明确策略一致，不静默吞错 |

## RAG、模型与 MCP

| 用例 ID | 用例名称 | 验收标准 |
| --- | --- | --- |
| RAG-001 | 意图定向通道启用 | 意图定向已开启且得分达到 `min-intent-score` 时执行定向检索 |
| RAG-002 | 全局向量通道回退 | 意图不满足高置信度条件时，按 `confidence-threshold` 和中置信度规则执行全局向量检索 |
| RAG-003 | 去重先于重排 | 候选合并后先去重；重排开启时才调用 Rerank，且顺序可观测 |
| RAG-004 | TopK 责任边界 | 仅 `RerankPostProcessor` 进行最终 TopK 截断；关闭 `rag.rerank.enabled` 后不存在隐式截断 |
| RAG-005 | 查询短路 | 澄清引导和纯系统回答场景不执行不必要的知识库检索 |
| RAG-006 | 流式取消与限流 | SSE 取消、超时或全局并发超限时资源得到释放，响应符合既有错误与事件协议 |
| AI-001 | 模型候选降级 | 首选 Chat、Embedding 或 Rerank 模型失败时按候选优先级、健康状态和熔断策略选择后备模型 |
| MCP-001 | MCP 工具失败 | 工具超时、参数非法或远端失败时返回可诊断结果，不阻塞或污染后续请求 |

## 文档处理、Trace 与前端

| 用例 ID | 用例名称 | 验收标准 |
| --- | --- | --- |
| ING-001 | 文档处理状态 | 上传、解析、分块、向量化成功与失败状态可追踪；重试不会重复写入不一致数据 |
| ING-002 | 结构化分块 | 表格、图片或结构化内容走对应处理分支，保留足够的来源与定位信息 |
| TRACE-001 | 链路追踪 | 开启 `rag.trace.enabled` 后，Trace 记录关键节点时延和失败信息，但不记录敏感内容或完整密钥 |
| FRONT-001 | 流式问答体验 | 加载、分片追加、取消、错误和自动滚动符合现有交互，浏览器控制台无新错误 |
| FRONT-002 | 管理端变更 | 知识库、意图、模型或 Trace 页面遵守现有 API 层、权限、加载和空态约定 |

## 需求专用用例

在此处为每个需求追加编号、输入、预期输出、依赖配置及自动化测试位置。修改阈值、排序、状态机、数据库结构或外部协议时，必须至少新增一条能证明变更的用例。
